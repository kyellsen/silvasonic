# ADR-0043: Python 3.14, until ai-edge-litert ships for 3.15

> **Status:** Accepted • **Date:** 2026-11-15

## 1. Context & Problem

The workspace pinned Python 3.13 (`requires-python = ">=3.13, <3.14"`, `.python-version`, `python:3.13-slim-bookworm` in every Containerfile). The house rule for Kyell's repositories is Python 3.15 everywhere, 3.14 only where a dependency ships no 3.15 wheel, and nothing below 3.14.

`ai-edge-litert`, the BirdNET inference runtime chosen in [ADR-0027](0027-birdnet-inference-engine.md), ships wheels for CPython 3.10 to 3.14 and none for 3.15 (checked 2026-11-13 against v2.3.0, its newest release): `uv lock -p 3.15` has no solution for `silvasonic-birdnet`. Every other locked package resolves on 3.14.

## 2. Decision

**We chose:** Python 3.14 for the whole workspace and every service image.

**Reasoning:**
3.14 is the newest release every dependency ships for. One version for all services keeps one lock and one base image; a birdnet image on 3.14 beside the rest on 3.15 would need a second lock.

- `.python-version` is `3.14`; the root `requires-python` is `>=3.14, <3.15`, each member's `>=3.14`; ruff targets `py314`.
- `scripts/` keeps the ruff target `py313` (`per-file-target-version`): the justfile runs those scripts with the host's system Python, which on a station or a CI runner may be older than the venv's.
- The lock moved only `ai-edge-litert`, 2.1.3 → 2.1.5, the oldest release with cp314 wheels.
- Every Containerfile builds on `python:3.14-slim-bookworm`: the same Debian release as before, so the system libraries (SQLite 3.40, ffmpeg, libsndfile) do not change.

## 3. Options Considered

* **Python 3.15**: Rejected for now — `ai-edge-litert` has no 3.15 wheel, and building it from source is not an option for the Raspberry Pi station.
* **3.15 for every service but birdnet**: Rejected — two interpreters mean two locks and two base images for one workspace.
* **Stay on 3.13**: Rejected — below the house floor of 3.14, with nothing that requires it.

## 4. Consequences

* **Positive:** The workspace is on a supported, current CPython; the move to 3.15 is a version bump once its one blocker is gone.
* **Negative:** The ruff formatter for the `py314` target writes PEP 758 `except A, B:` without parentheses, so the service code no longer parses on 3.13; going back would need a reformat.
* **Follow-up:** Move to 3.15 when `ai-edge-litert` publishes cp315 wheels for `linux_x86_64` and `linux_aarch64`: raise the bounds, `uv lock -p 3.15`, the base images, and supersede this ADR.
