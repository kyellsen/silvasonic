# Glossary

> **Authority:** This glossary defines the canonical domain language for the Silvasonic project.
> All documentation, code, and communication **MUST** use these terms consistently.
> See also: [AGENTS.md §2](AGENTS.md) — Domain Language Policy.

---

## Services & Roles

| Term              | Definition                                                                                                                                                                                                                                                                                                                                                        |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **BatDetect**     | (Planned) Tier 2 on-device inference service (single instance) for bat species classification. Consumes Processed recordings (read-only).                                                                                                                                                                                                                         |
| **BirdNET**       | Tier 2 on-device inference service (single instance) for avian species classification using native TFLite. Consumes Processed recordings (read-only) and extracts Audio Clips.                                                                                                                                                                                                                       |
| **Controller**    | Tier 1 orchestration service (single instance). Detects USB microphones, manages Tier 2 container lifecycles (start/stop/reconcile), provisions workspaces, and publishes heartbeats to Redis. Follows the State Reconciliation Pattern — reads desired state from DB, subscribes to `silvasonic:nudge` for immediate wake-up. Has no HTTP API beyond `/healthy`. |
| **Database**      | The station database: one SQLite file shared by every service with DB access (ADR-0037). Central state management for all services with DB access.                                                                                                                                                                                                                                               |
| **Gateway**       | (Planned) Tier 1 Caddy-based reverse proxy (single instance) handling HTTPS termination, internal routing, and authentication.                                                                                                                                                                                                                                    |
| **Icecast**       | (Planned) Tier 1 streaming server (single instance). Receives live Opus audio from Recorder instances via mount points and serves it via HTTP to the Web-Interface and external clients.                                                                                                                                                                          |
| **Janitor**       | Logical role within the Processor service responsible for enforcing the Data Retention Policy by deleting old files based on disk usage thresholds.                                                                                                                                                                                                               |
| **Processor**     | Tier 1 service (single instance) for data ingestion, indexing, cleanup, and cloud sync. Contains the Janitor and Cloud-Sync-Worker (v0.6.0). **Immutable** — config at startup, restart to reconfigure (ADR-0019).                                                                                                                                        |
| **Recorder**      | Tier 2 audio capture service. Captures audio via FFmpeg subprocess (ADR-0024), writes dual-stream output (Raw & Processed) to NVMe, and sends a live Opus stream to Icecast (best-effort). Immutable, no DB access, config via Profile Injection (Microphone Profiles). **Multi-instance: one Recorder per microphone.**                                                                     |

| **Singleton Worker**<br>**(Background Worker)** | A Tier 2 service restricted to exactly one running instance across the entire system. Responsible for cluster-wide asynchronous processing like ML inference. Implements the Worker Pull pattern. Lifecycle is managed by the Controller via the `modules` table. |
| **Weather**       | (Planned) Tier 2 service (single instance). First downloads environmental data from external APIs (e.g. OpenMeteo) and stores it in the database, then correlates it with acoustic recordings.                                                                                                                                                                    |
| **Web-Interface** | (Planned) Tier 1 local management console targeting production use (single instance). Uses the Read+Subscribe Pattern (Redis SET+TTL + Pub/Sub) for real-time service status. Controls services via DB writes + `PUBLISH silvasonic:nudge "reconcile"` (State Reconciliation Pattern). |
| **Web-Mock**      | Tier 1 development prototype and UI shell (single instance). FastAPI + Jinja2 + HTMX serving hardcoded mock data. Precursor to the full Web-Interface. Uses `ServiceContext` lifespan. Port 8001. |

## Database Entities

| Term                    | DB Table              | Definition                                                                                                                                                                                                                                                               |
| ----------------------- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Detection**           | `detections`          | A time-bounded classification result produced by an Analyzer (e.g. BirdNET). Links to a Recording and a Species; carries a confidence score, the label as the analyzer reported it (`label`), the Species it means (`species_id`) and its review state (`review_state`). Keyed by its UUIDv7 `id`, indexed by `started_at` (ADR-0037). |
| **Microphone**          | `microphones`         | Inventory entry for a physical microphone, the persisted entity that was once called "Device". `id` is a UUIDv7; `hardware_id` is the Stable Device ID; `name` is a label the user chooses (the model until then). Tracks `enrollment_state`, `connection_state` (`connected`/`disconnected`), `first_seen_at`, `last_seen_at`, the facts read from the hardware (`hardware`), and links to a Microphone Profile. "Device" remains the word for the physical USB/ALSA hardware. |
| **Microphone Profile**  | `microphone_profiles` | Configuration template for a specific microphone type. Defines match patterns for auto-detection, sample rate, channels, and recording parameters. Injected into Recorder via Profile Injection.                                                                         |
| **Recording**           | `recordings`          | Registry entry for an audio file pair (Raw + Processed) captured by a Recorder instance. Tracks duration, sample rate, file sizes, upload status, and analysis state. Referenced by `detections` and `uploads` (ADR-0025). |

| **Settings**            | `settings`            | Application-wide settings, one JSONB row per section (`station`, `recording`, `storage`, `sync`, `birdnet`, `auth`), validated by Pydantic schemas. `revision` starts at 1 and grows with every write. |
| **Module**              | `modules`             | An optional feature the user switches on or off, whichever process implements it (replaces "Managed Service"). `id` is a slug such as `birdnet` or `cloud_sync`; `enabled` is the desired state. The Controller starts and stops the Tier-2 singletons (BirdNET, BatDetect, Weather) from these rows; the Processor reads `cloud_sync` for the upload. Multi-instance Tier-2 services (Recorder) derive state from domain tables (`microphones`). Domain/business settings (thresholds, intervals) remain in `settings`. See ADR-0017, ADR-0029. |
| **Species**             | `species`             | Metadata registry for every class an Analyzer reports (replaces "Taxonomy"). `id` is a slug of the scientific name (e.g. `turdus-merula`); `analyzer` + `label` is how an analyzer names it. Holds localized `common_names` and `descriptions`, a `category` (`bird`, `bat`, … `human`, `environment`, `other` for non-species sound classes), the `watched` flag, images and conservation status (IUCN). |
| **Upload**              | `uploads`             | Immutable audit log entry for a single upload attempt. Links a Recording to a Storage Remote and records success/failure, file size, and errors.                                                                                                                         |
| **Weather Observation** | `weather_observations` | Environmental data point from a local sensor (e.g. BME280) or external API (e.g. OpenMeteo). Keyed by observation time and source.                                                                                                                                 |

## Architecture & Domain Concepts

| Term                                      | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Actual State**                          | Runtime health and activity of a service (healthy/degraded/crashed). Published to Redis by each service via the SilvaService heartbeat: `SET silvasonic:status:<id>` with TTL (current snapshot) + `PUBLISH silvasonic:status` (live updates). Web-Interface uses the Read+Subscribe Pattern. Not persisted in the database. See ADR-0017, ADR-0019.                                                                                                                                                                                          |
| **Analysis Backlog**                      | The logical queue of unprocessed recordings waiting for inference. Managed dynamically via atomic DB queries (a short claim, `UPDATE … RETURNING` with a lease, ADR-0037) where the row lacks the specific worker's key in its `analysis_state` JSON. Processed continuously by Singleton Workers.                                                                                                                                                                                                                                                                           |
| **Analyzer**                              | What produced a Detection: the analysis Module that classified the audio (e.g. `birdnet`, `batdetect`), stored as `detections.analyzer`. Its result per recording is an entry in `recordings.analysis_state`: `{"state": "done"|"failed"|"skipped", "reason", "finished_at", "detection_count"}`, or `{"state": "running", "claimed_at"}` while it works. "Worker" names how it runs, not what it is. |
| **Audio Clip**                            | A short, extracted WAV file representing the exact time window of a specific biological Detection (e.g., a bird call) plus some configurable padding. Resides in the worker's workspace and is referenced by `detections.clip_path`. Used for user playback and manual verification.                                                                                                                                                                                                                                              |
| **Auto-Enrollment**                       | Feature where the Controller automatically enrolls a newly detected USB device if it has an exact Match Criteria hit (score 100 = USB Vendor+Product ID). Controlled by the `auto_enrollment` flag in `settings` (section `recording`). Default: `true`. Can be changed at runtime via the Web-Interface — the Controller reads this setting every reconciliation cycle (no restart required). See [Controller README §Profile Matching](https://github.com/kyellsen/silvasonic/blob/main/services/controller/README.md).                                                                        |
| **Consumer Principle**                    | Any service consuming data it did not create MUST mount that data read-only (e.g. BirdNET and BatDetect mount Recorder data as read-only). Protects source data from software faults.                                                                                                                                                                                                                                                                                                                                                         |
| **Data Capture Integrity**                | The paramount design principle: any operation that risks the continuity of sound recording is forbidden. All architectural decisions are subordinate to this rule.                                                                                                                                                                                                                                                                                                                                                                            |
| **Data Retention Policy**                 | Rules enforced by the Janitor for deleting old local files based on disk usage thresholds. Recordings are only deleted after confirmed upload.                                                                                                                                                                                                                                                                                                                                                                                                |
| **Desired State**                         | The intended operational mode of a Tier-2 singleton, stored in the `modules` table (`enabled`). Set by admin or Web-Interface. For Recorders, desired state is derived from `microphones` + `microphone_profiles`. Not to be confused with Actual State. See ADR-0017, ADR-0029.                                                                                                                                                                                                                                                   |
| **Device Binding**                        | Persistent identification of a physical microphone via a Stable Device ID. Devices with USB serial numbers are identified as `{vendor_id}-{product_id}-{serial}` (globally unique). Devices without serials use `{vendor_id}-{product_id}-port{bus_path}` (stable per USB port). The Stable Device ID is stored as `microphones.hardware_id` (unique) and determines Recorder name, workspace path, and Redis instance ID. Re-plugging a microphone re-activates the same Recorder. See [Controller README §Device Identity](https://github.com/kyellsen/silvasonic/blob/main/services/controller/README.md). |
| **Microphone Enabled Flag**               | Boolean flag on the `microphones` table (`enabled`, default `true`). When set to `false`, the Controller immediately stops the Recorder for this Microphone regardless of Enrollment State. Acts as an emergency stop.                                                                                                                                                                                                                                                                                                                               |
| **DeviceScanner**                         | Controller component that performs a full scan of all ALSA sound cards via `/proc/asound/cards`, correlates each with its USB parent via `sysfs`, and synchronizes the result with the `microphones` table. Runs every reconciliation cycle (1 s interval) as the primary USB detection mechanism. See [Controller README §USB Detection](https://github.com/kyellsen/silvasonic/blob/main/services/controller/README.md).                                                                                                                                                                           |
| **Domain-Driven Workspace Isolation**     | Each service owns exactly one top-level directory in the Workspace matching its service name. No shared folders for persistent state. Enforces the Single Writer principle.                                                                                                                                                                                                                                                                                                                                                                   |
| **Dual Stream Architecture**              | Recording strategy producing two simultaneous outputs per microphone: Raw (native sample rate) and Processed (48 kHz). Ensures hardware independence for downstream consumers. |
| **Enrollment State**                      | The state of a Microphone in its registration lifecycle (`enrollment_state`): `pending` (new/unassigned), `enrolled` (assigned a Microphone Profile, eligible for recording), `ignored` (suppressed — Controller will never start a Recorder for this Microphone). Tracked in the `microphones` table.                                                                                                                                                                                                                                                                         |
| **Factory Reset**                         | Deletion of all content within the Workspace path. The directory structure is immediately reconstructible by re-running the init script.                                                                                                                                                                                                                                                                                                                                                                                                      |
| **Filesystem Polling**                    | Communication pattern where the Processor watches the Recorder's workspace directories for new audio files, then indexes them into the database. See [Messaging Patterns](arch/messaging_patterns.md).                                                                                                                                                                                                                                                                                                                                        |
| **Heartbeat**                             | Periodic status message published by each service to Redis via the `SilvaService` base class (interval: see `DEFAULT_HEARTBEAT_INTERVAL_S` in `heartbeat.py`). Contains service name, instance ID, health status, activity, and optional metadata. Fire-and-forget — failures are silently caught. See ADR-0019.                                                                                                                                                                                                                                                                                   |
| **Immutable Container**                   | A service that receives all configuration at launch time and never modifies its own state. All Tier 2 services plus the Processor (Tier 1) are immutable. The Recorder has no DB access; other immutable services may access the database. See ADR-0019.                                                                                                                                                                                                                                                                                      |
| **Live Log Stream**                       | Real-time container log feed published via `PUBLISH silvasonic:logs` (Redis). The Controller reads Podman container stdout (structlog JSON) and forwards it to Redis. The Web-Interface subscribes and displays logs via SSE + Alpine.js auto-scroll. Fire-and-forget — if no subscriber is connected, logs are simply not displayed. See [ADR-0022](adr/0022-live-log-streaming.md).                                                                                                                                                         |
| **Live Stream**                           | (Planned) Real-time audio stream in Opus format, sent from a Recorder to the Icecast server (one mount point per microphone). Enables live monitoring of the soundscape via the Web-Interface without accessing stored recordings. Best-effort: does not compromise Data Capture Integrity.                                                                                                                                                                                                                                                             |
| **Match Criteria**                        | Structured data within a Microphone Profile that defines how to match a USB device to that profile. Contains `usb_vendor_id`, `usb_product_id` (primary, stable), and `alsa_name_contains` (secondary, case-insensitive substring). Stored in the profile's `config` JSONB column under `audio.match`. See [Microphone Profiles](arch/microphone_profiles.md).                                                                                                                                |
| **Mount Point**                           | (Planned) An Icecast endpoint path (e.g. `/mic-ultramic.opus`) representing one audio source. Each Recorder pushes to its own mount point; the Web-Interface selects which mount point to listen to.                                                                                                                                                                                                                                                                                                                                                    |
| **OOM Killer**                            | Linux kernel mechanism that terminates processes when physical memory is exhausted. Silvasonic mitigates this via `oom_score_adj` and container memory limits (ADR-0020).                                                                                                                                                                                                                                                                                                                                                                     |
| **OOM Score Adjust** (`oom_score_adj`)    | Linux kernel parameter (-1000 to +1000) that biases the OOM Killer's target selection. Lower values = less likely to be killed. The Recorder uses -999 (maximum protection); analysis workers use +500 (expendable). See ADR-0020.                                                                                                                                                                                                                                                                                                            |
| **Opus**                                  | (Planned) Lossy audio codec optimized for low-latency, high-quality streaming. Used exclusively for the live audio stream (Recorder → Icecast). Not used for archival — Raw and Processed recordings remain WAV/FLAC.                                                                                                                                                                                                                                                                                                                                   |
| **Processed Artifact** (`processed_path`) | The standardized 48 kHz version of an audio recording, derived from the raw stream. Used as input for analysis (BirdNET, BatDetect), visualization, and consumption. Local format: WAV.                                                                                                                                                                                                                                                                                                                                                       |
| **Profile Injection**                     | The mechanism by which the Controller injects Microphone Profile configuration into Recorder containers via environment variables at creation time. Applies exclusively to the Controller ↔ Recorder relationship.                                                                                                                                                                                                                                                                                                                            |
| **QoS (Quality of Service)**              | Tiered resource priority scheme ensuring critical services (Recorder) are never starved by optional services (BirdNET, BatDetect). Implemented via `oom_score_adj` and resource limits (ADR-0020).                                                                                                                                                                                                                                                                                                                                            |
| **Quadlet**                               | Podman-native systemd unit files (`.container`, `.volume`, `.network`) used for production deployment. Ensures automatic restart after power loss without compose.                                                                                                                                                                                                                                                                                                                                                                            |
| **Raw Artifact** (`raw_path`)             | The bit-perfect copy of the audio stream at the hardware's native sample rate. Preserved strictly for archival and scientific purposes; never modified. Local format: WAV. Cloud format: FLAC.                                                                                                                                                                                                                                                                                                                                                |
| **Read+Subscribe Pattern**                | Two-step pattern used by the Web-Interface to display service status: (1) read all `silvasonic:status:*` keys for initial state, (2) subscribe to `silvasonic:status` for live updates. Solves the Pub/Sub "missed heartbeat" problem. See [Messaging Patterns](arch/messaging_patterns.md).                                                                                                                                                                                                                                                  |
| **Reconcile-Nudge**                       | A simple `PUBLISH silvasonic:nudge "reconcile"` signal sent by the Web-Interface after a DB write to wake the Controller immediately instead of waiting for its reconciliation timer. Not a command — just a wake-up signal. If lost, the timer catches up. See [Messaging Patterns](arch/messaging_patterns.md).                                                                                                                                                                                                                                        |
| **Reconciliation**                        | The Controller's periodic process of comparing desired vs. actual Tier 2 container state and correcting drift (adopting orphans, restarting missing containers). Interval: see `DEFAULT_RECONCILE_INTERVAL_S` in `reconciler.py`.                                                                                                                                                                                                                                                                                                                                                                      |
| **Repository**                            | The immutable code directory (`SILVASONIC_REPO_PATH`) containing source code, scripts, and configuration templates. Containers have read-only access in production.                                                                                                                                                                                                                                                                                                                                                                           |
| **Resource Limits**                       | Podman container constraints (`--memory`, `--cpus`) enforced via Linux cgroups v2. Prevents any single container from exhausting host resources. See ADR-0020.                                                                                                                                                                                                                                                                                                                                                                                |
| **ServiceContext**                        | Shared infrastructure primitive used directly by HTTP/FastAPI services via lifespans. |
| **SilvaService**                          | Base class (`silvasonic.core.service.SilvaService`) providing the canonical lifecycle for background worker services and immutable containers: logging, health server, Redis connection, heartbeat, signal handling. See ADR-0019. |
| **Soundscape**                            | The complete acoustic environment captured by the system — from low-frequency avian vocalizations to ultrasonic bat echolocation calls. Not limited to a single species or frequency band.                                                                                                                                                                                                                                                                                                                                                    |
| **State Reconciliation Pattern**          | Declarative control pattern inspired by Kubernetes Operators. The Web-Interface writes desired state to DB, sends a Reconcile-Nudge, and the Controller reconciles. The Controller has no imperative API — it is a pure Listener + Actor. See ADR-0017.                                                                                                                                                                                                                                                                                       |
| **Station**                               | The whole Silvasonic unit — one Raspberry Pi with its microphones, services and storage. In fleet language it is the "device"; within Silvasonic "device" only means USB hardware. Its identity is the `station` settings section (`id` — a UUIDv7 generated once at first boot — `name`, `latitude`, `longitude`). |
| **Store & Forward**                       | Architecture pattern where recordings are written to local NVMe first. Synchronization to remote storage happens opportunistically — the station never depends on network connectivity.                                                                                                                                                                                                                                                                                                                                                       |
| **Tier 1 (Infrastructure)**               | Services managed by Podman Compose (dev) or Quadlets (prod). Always running. Includes Database, Controller, Gateway, Icecast, Processor, Web-Interface, Redis, Tailscale.                                                                                                                                                                                                                                                                                                                                                                     |
| **Tier 2 (Application)**                  | Services managed dynamically by the Controller at runtime. All Tier 2 containers are immutable. Includes Recorder, BirdNET, BatDetect, Weather.                                                                                                                                            |
| **Worker Pull**                           | Orchestration pattern where analysis workers (BirdNET, BatDetect) independently poll the `recordings` table for unprocessed files, claiming work atomically via a short claim (`UPDATE … RETURNING` with a lease, ADR-0037). See ADR-0018.                                                                                                                                                                                                                                                                                                                              |
| **Workspace**                             | The mutable state directory (`SILVASONIC_WORKSPACE_PATH`) where all runtime data (recordings, configs, service state) is persisted. Strictly separated from the immutable code repository.                                                                                                                                                                                                                                                                                                                                                    |
